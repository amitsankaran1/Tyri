Two steps, one ordinary block

1 · Build lists

Choose the distractions that matter to you

Optional Social media, Games, and Scrollers starters, plus custom lists. Suggestions explain what to consider; the person selects actual apps in Apple’s picker.

Skippable on first launch. Reopen from Lists. Apps can appear in more than one list. Existing users get an optional entry point.

2 · Describe a block

“Social media and Games, weekdays 9am–5pm”

Interpret one block’s target lists and timing, resolve missing details, and show the native editable review. Only the person’s confirmation saves the block.

Missing list → name/choose apps → save list → return to the preserved block draft.

Accepted scope: recurring weekly schedules, repeating usage allowance/lockout cycles, and NFC-tag blocks. One-time dates and temporary-duration blocks are outside this natural-language version; the separate manual temporary-block flow remains available.

What the model never controls: app tokens, installed-app enumeration, database writes, permissions, monitoring callbacks, or activation. Swift validates and saves through Tyri’s existing managers.

Finite choices

Lists, block type, weekdays

Use one target question per saved list, one block-type choice, and seven day questions. Several lists can be included at once.

Finite, but decomposed

Exact times and durations

Hour and minute components fit below Jev’s 255-option limit. Their independent answers can disagree, so numbers still require validation and accuracy tests.

Needs another input

Names and missing intent

Jev cannot create a new list name or a written follow-up. A name field and fixed clarification controls handle these; optional text extraction is a separate path.

Important distinction: “a finite value exists” does not prove “independent classification questions recover it correctly.” The benchmark must test relations: which duration is usage, which is lockout, and which list belongs to which schedule.

A smaller candidate-based alternative
Instead of asking Jev to reconstruct numbers digit by digit, a local parser can supply exact candidates from the sentence, then Jev chooses their roles.
“Allow 40 minutes on Scrollers, then block for 50 minutes.”
candidate_a = 40 minutescandidate_b = 50 minutes
usage_value → {candidate_a, candidate_b, missing, ambiguous, not_applicable}
lockout_value → the same five choices
Expected answers: usage = candidate_a; lockout = candidate_b. Code preserves 40 and 50 exactly.
Trade-off: this moves number and date-language coverage into the local parser. “An hour and a half,” “half past nine,” locale-specific clocks, and multiple occurrences all need tests. If a candidate is missing, ask the person or use a separately evaluated fallback; never substitute the nearest candidate.
Limit the number of candidates per question, deduplicate exact equivalents, preserve their source spans, and include “not represented.” A parser failure must not force a plausible-looking wrong choice.


The local consistency gate
User text + saved lists→Typed answers→Consistency checks→Clarify / create list / review→User confirms save
  1. Route first: any unsupported requirement, multiple blocks, or unresolved ambiguity prevents a draft. Never drop an inconvenient clause.
  2. Resolve lists: require at least one included, existing ID; expand “all except” against the current snapshot. Prefill an unknown name when an exact source span is clear; otherwise ask. The name stays editable. “Shopping — choose apps to finish this list” must make the unconfigured state obvious. Never fabricate a name.
  3. Weekly: nonempty valid start days; complete start and end, or locally derived midnight bounds after explicit all-day intent; at least 15 minutes; equal times only for explicit all-day intent. Disclose overnight start-day ownership and device-local time.
  4. Usage: both exact positive durations; accepted bounds; native picker selections; repeating cycles and midnight reset disclosed. A daily cap cannot be silently converted.
  5. NFC: ignore irrelevant timing outputs; check tag registration locally. Never enable the block just because the model picked NFC.
  6. Access settings: explicit choices win. Unspecified fields show the existing 5-minute early-stop wait and no-break default. Reject timer-plus-break contradictions.
  7. Before saving: recheck current lists, selected contents, permissions, and all edited fields. Handle saved-but-not-running results truthfully.
A high-confidence answer can still be wrong. Confidence may guide clarification, but never bypasses local checks or the person’s review. Thresholds must be calibrated on Tyri examples.

Do not assume a Jev → Luna cascade. Start with three comparable alternatives. A fallback earns its place only if it improves measured coverage, latency, or cost. All three must lead to the same editable block review.
Proposed evaluation gate
  • Freeze 120 human-labeled cases before comparison: 24 intent families shown above with independently written variants. Keep a separate tuning set.
  • Record full-plan correctness, silent wrong-plan count, correct and unnecessary clarification, missing-list name recovery, exact numbers, and exclusion handling. Also measure user corrections, extra actions, completion without retyping, and abandonment; abstaining on every case is not success.
  • Measure p50/p95 end-to-end latency and provider cost per accepted plan; include retries and clarification. Vendor speed claims are not Tyri measurements.
  • Require zero silent wrong-plan cases in the frozen release corpus and all deterministic invariants passing. Report the corpus size and remaining risks; this is not a universal accuracy claim.
  • Use real device testing separately for App Attest, picker selections and enforcement. Model interpretation tests cannot prove blocking works.
Current conclusion: Jev is a credible candidate, not yet the selected provider.
The saved-list/type/day choices are natural fits. Exact parameters can be modeled without preset snapping. The deciding evidence is complete-plan accuracy and user friction, especially for unknown lists, ambiguity, and relational sentences.

What remains a product decision
The accepted product flow is fixed. The unresolved choice is the interpretation engine. If Jev needs a restricted vocabulary or noticeably more follow-ups, that changes the user experience and must be weighed against any measured speed or cost gain.
Block names can be generated deterministically from selected lists and type, then edited. New list names require user input or an extraction path. Neither is a reason to pretend Jev generates arbitrary text.
